# Agent Town, Plan 3: Dialogue box, sending and permissions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** From the town, the user opens an RPG dialogue box for any worker, answers its permission prompt, sends it its next instruction, sees a quest log of everything waiting on them, and can jump to the session's own window.

**Architecture:** The daemon learns each session's Claude process id from the hook and gains `POST /api/town/open`, which brings that session's window to the front. The web UI reports town focus to the daemon (a heartbeat inside the 15 s lease from plan 1), so `PermissionRequest` hooks wait for a town answer while the town is focused. Pure modules build the dialogue content, the quest list and worker hit-testing; `DialogueBox.tsx` and `QuestLog.tsx` render them inside `TownView`.

**Tech Stack:** .NET 10 (ASP.NET Core minimal APIs, Win32 via P/Invoke), xUnit; React 19, TypeScript, Vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-10-27-agent-town-design.md`

**Series:** Plan 3 of 5. Plans 1 (backend) and 2 (town screen) are merged. Plan 4: tray blink, Windows notifications, sounds, settings. Plan 5: boss character, XP and levels, building growth. Focus reporting moves from plan 4 into this plan (*ruling*: the permission menu cannot work without it).

## Global Constraints

- Nothing may block or delay real work. A town answer only ever adds a faster path; the session window always keeps its own dialog when the town does not answer.
- "Town focused" means the main window has focus and is in town mode. Report it with `POST /api/town/focus {"focused":true}` every 5 s while true (the daemon's lease is 15 s, `PermissionBroker.DefaultFocusLease`), and `{"focused":false}` at once when it stops being true (window deactivated, page hidden, town left, view unmounted).
- The messaging token never reaches the browser: the web UI only calls `/api/town/send` with a session id and text.
- Dialogue box (mockup `docs/superpowers/specs/agent-town/chat-box-v2.html`): bottom of the screen; large pixel portrait of the worker on the left in its hat and shirt colours with a mood badge `!` (waiting) or `✓` (done); a name tag on the frame coloured by state, e.g. "KODEX · Session A"; text that types out letter by letter with a blinking ▼; the town dims slightly behind it; Esc closes it.
- Opens by clicking a worker, Tab (cycles workers that need the user), or a quest in the quest log. (Enter next to a worker needs the boss character: plan 5.)
- Permission prompt: first person, generated by the town: `Boss! I need to run a command first: \`<command>\` Can I?` for Bash/PowerShell, `Boss! I need to use <Tool> first. Can I?` otherwise. Menu "Go ahead / Always OK / No, don't", arrow keys and Enter. Go ahead = `allow`, Always OK = `allow` + `always`, No, don't = `deny`.
- Done: Claude's last message unchanged, plus a `>` input line. Enter sends, Shift+Enter makes a new line.
- Working: the current prompt and recent tools, plus the same `>` input line.
- Waiting on a question (elicitation), or a prompt that is not answerable from the town: show the question and "Open window" ("Answer in the window").
- Every box has "Open window".
- If sending fails, the box says so and offers "Open window"; the typed text stays in the input.
- Quest log (key Q): everything waiting on the user, with how long it has waited; needs-you first, then done sessions not yet seen. Opening a done session's dialogue marks it seen; seen done sessions drop off the quest log but stay done on the street. Clicking a quest opens that dialogue.
- Honour `prefers-reduced-motion`: text appears at once, ▼ does not blink.
- No sounds, XP or notifications in this plan.

## Review Focus

1. **Focus lost while a prompt waits** (user alt-tabs to the session window). Expected: the page reports `focused:false` at once, the hook returns "no decision", the prompt becomes "Answer in the window" in the open box. Test in Task 2 (heartbeat stops and false is posted on blur) and Task 6 (box switches to the window message).
2. **Answer arrives after the prompt was already released or answered in the window.** Expected: the answer call returns `Ok=false`; the box says "Already answered in the window" and closes the menu; no error toast. Test in Task 5.
3. **Session ends while its box is open.** Expected: the box closes; no crash. Test in Task 6.
4. **Typing in the input.** Expected: Q, Tab, arrows, Home and Esc-for-the-town do not fire while the input has focus, except Esc, which closes the box. Test in Task 6.
5. **A click that ends a drag.** Expected: dragging the street never opens a dialogue; only a press and release within 4 px does. Test in Task 6.

**Interfaces:**

- Produces (Core):

  - `static class ProcessTree { static IReadOnlyList<(int Pid, string Name)> Ancestors(int pid); static int? FindAncestor(int pid, Func<string, bool> nameMatches); }` (`Ancestors` excludes `pid` itself, nearest first, stops at a cycle or pid 0; names are exe file names like `claude.exe`).

- `TownHook`: `ClaudePid = ProcessTree.FindAncestor(Environment.ProcessId, n => n.StartsWith("claude", OrdinalIgnoreCase))`. The snapshot takes a few ms; keep it inside the existing 1 s budget.

### Task 3: Dialogue content and quests

**Files:**
- Create: `web/src/lib/town/dialogue.ts`, `web/src/lib/town/quests.ts` (+ tests)
- Modify: `web/src/state/reducer.ts` (+ test)

**Interfaces:**
- Produces (state): `AppState.agentLog: Record<string, string[]>`, the last 5 distinct `message` values per session, oldest first, appended in the `agent` case when `message` changed; dropped in `agentEnd`; `agentsLoaded` seeds one entry per session.
- Produces (dialogue.ts):
  - `type DialogueKind = 'permission' | 'answerInWindow' | 'question' | 'done' | 'working' | 'idle' | 'failed'`
  - `interface Dialogue { kind: DialogueKind; nameTag: string; mood: '!' | '✓' | null; text: string; prompt?: PermissionPromptDto; canSend: boolean }`
  - `dialogueFor(session: AgentSessionDto, lotName: string, indexInLot: number, log: string[]): Dialogue`
  - `speechFor(prompt: PermissionPromptDto): string`
  - `sessionLetter(index: number): string` (`0 → 'A'`, `25 → 'Z'`, `26 → 'AA'`).
- Rules: `nameTag = lotName.toUpperCase() + ' · Session ' + sessionLetter(index)`. Kind: first answerable prompt → `permission` (text = `speechFor`); any non-answerable prompt → `answerInWindow` (text: `"I asked in my window: <summary>. Answer it there."`); state `waiting` with no prompts → `question` (text = `message`); `done` → text = `lastReply ?? message`, unchanged; `working` → `"Working on: <prompt>"` then a blank line then the `log` lines; `idle` → `"Ready when you are."`; `failed` → `"Something broke: <message>"`. `mood`: `!` for permission/answerInWindow/question, `✓` for done, else null. `canSend` = `session.canSend && kind in done|working|idle|failed`.
- Produces (quests.ts): `interface Quest { sessionId: string; lotName: string; kind: 'needsYou' | 'review'; title: string; since: number }`; `questsFor(lots: Lot[], seen: Record<string, string>): Quest[]`; `waitText(ms: number): string` (`"just now"` < 60 s, `"3 min"`, `"2 h 5 min"`). Needs-you = `waiting` sessions, title `"<lot>: <message>"`; review = `done` sessions whose `seen[id] !== since`, title `"Review <lot>'s result"`. Sort: needs-you by since ascending, then review by since ascending.

Behaviour:
- Text types out at 40 characters per second (`setInterval`); clicking the text or pressing Space finishes it at once; ▼ blinks when finished and more is hidden (here: never more than one page; ▼ marks "done typing"). Reduced motion: full text at once, no blink.

- "Open window" button: `api.townOpen(session.id)`; failure shows its message in the box.
- Esc closes (calls `onClose`), also from inside the textarea.
